# Run on another laptop

Clone the repository and run the commands from its directory. Python 3.12 is the tested version. Install Git, Python 3.12, and FFmpeg (both `ffmpeg` and `ffprobe` on PATH). On Windows with NVIDIA, bootstrap downloads the pinned CUDA llama.cpp runtime used by the original laptop; a compatible NVIDIA driver is required. For other hardware, install a compatible [llama.cpp release](https://github.com/ggml-org/llama.cpp/releases) containing `llama-server`, with its companion libraries in the same directory, and pass `--llama-server`. On macOS/Linux the executable is normally `llama-server`; on Windows it is `llama-server.exe`.

The bootstrap downloads public models only. Keep at least 15 GB free for environments, verifier weights, and perception assets; allow additional space for videos and evidence. Setup needs internet and can take substantially longer than five minutes. Video inference runs locally after installation. A dedicated GPU is recommended. CPU mode is available for compatibility, but is unlikely to finish every review within the fixed 300-second deadline. The default Qwen3-VL-4B Q4_K_M model and matching F16 projector match the profile used by the original laptop. Hardware speed and memory fit still need validation on each laptop. Start with 16 GB system RAM or more and benchmark the actual device; weight file size does not establish VRAM fit.

Windows PowerShell:

```powershell
$env:GIT_LFS_SKIP_SMUDGE = '1'
git clone https://github.com/alishka07/hack_data.git
cd hack_data
py -3.12 scripts/bootstrap_local.py
py -3.12 scripts/run_portable.py
```

macOS/Linux:

```sh
GIT_LFS_SKIP_SMUDGE=1 git clone https://github.com/alishka07/hack_data.git
cd hack_data
python3.12 scripts/bootstrap_local.py --llama-server /absolute/path/to/llama-server
python3.12 scripts/run_portable.py
```

Use `--ffmpeg` and `--ffprobe` with absolute paths if they are not on PATH. For another Windows runtime, pass `--llama-server 'C:\tools\llama\llama-server.exe'`. CPU mode requires both `--cpu` and `--llama-server` pointing to a CPU-compatible build. Inspect preparation without downloads using `python scripts/bootstrap_local.py --plan`. A second setup reuses environments and checksum-valid model files; OWLv2 setup may download its files again. `--skip-model-downloads` is only for a machine whose required assets and runtime are already installed.

The clone commands skip legacy Git LFS model downloads. The current application obtains its required public models through bootstrap instead.

Bootstrap installs pinned application dependencies into `.venv`, ByteTrack and RTMPose support there, and CPU Torch/OWLv2 dependencies into a separate `.venv-perception`. It runs the public YOLOX, RTMPose, OWLv2, and pinned Qwen3-VL-4B Q4_K_M plus matching F16 projector installers. Those scripts retain license/provenance and verify model identities. Runtime downloads occur during explicit setup only. Do not copy an arbitrary projector from a different model.

Open [the local UI](http://127.0.0.1:8000), read your new key from `data/api-key.txt`, paste it into the UI, and wait for **Worker ready** before uploading `.mov`. The launcher also accepts `--show-key` to explicitly print your key locally. Stop with Ctrl+C. Use `python scripts/run_portable.py --port 8001` if 8000 is occupied. Only one analysis runs at a time; the UI reconnects to it when the key is entered after refreshing.

Machine paths are saved to ignored `data/local-runtime.json`; they are regenerated by setup. Shell `FORTE_*` variables override these defaults. `.env.example` documents settings but is not loaded automatically. To switch to your own compatible verifier, set `FORTE_MODEL_PATH` and `FORTE_MMPROJ_PATH`, keeping their matching pair. Do not set `FORTE_ATTACH_MODEL=1` unless you are deliberately managing an already-running loopback model server.

The repository includes application code, UI, rule registry, setup scripts, and tests. It excludes private `open/` and `clips/` videos, source spreadsheets, model weights, environments, API keys, uploads, job databases, and generated evidence. They are unnecessary to launch and upload a new video. Training and reproducing private-data evaluations require separately authorized source data. No model has been fine-tuned by this setup. A result can explicitly report incomplete verification; inspect its coverage before treating it as a completed check.

For local checks after setup:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/setup_architecture_models.py --pose --objects --check-only
.\.venv\Scripts\python.exe scripts/setup_local_runtime.py --check-only
```

On macOS/Linux substitute `.venv/bin/python`. The model checks use installed assets offline and may take time; they do not establish detection accuracy or the video deadline. The current app was exercised on Windows; these portable entry points handle POSIX paths, but a full clean macOS/Linux install has not yet been tested.
