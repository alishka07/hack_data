ПРОВЕРКА НАРУШЕНИЙ НА ЗАПИСИ КАССЫ

Адрес: http://127.0.0.1:8765
Запуск: откройте «Открыть веб-страницу.cmd» в D:\open\case.
Или в терминале: cd D:\open\case, затем python launch_web.py.
Используется глобальный Python. Приложение нужно оставить работающим.

КАК ПОЛЬЗОВАТЬСЯ

1. Выберите видео или перетащите файл на страницу.
   MOV, MP4, AVI, MKV, M4V, WebM; до 512 МБ, если кодек читается.
2. Нажмите «Проверить нарушения». Выбирать модели и интервал не нужно.
   Автоматически запускаются три модели и проверка состояний двери/сейфа,
   последовательно. Дополнительные переключатели не нужны.
3. Просмотрите возможные эпизоды: время, основание, исходный кадр и
   ограничения вывода. Нажмите время, чтобы перейти к нужному моменту.
4. Посмотрите охват правил: часть правил пока не проверяется автоматически.
5. Скачайте отчёт HTML, CSV, JSON или общий ZIP с кадрами и видеокопиями.
   Для просмотра кадров в HTML сначала распакуйте весь ZIP.

Объекты, рамки и траектории остаются во вспомогательном разделе.
Повторные наблюдения связываются в эпизоды. Один предмет сам по себе
не является нарушением.

ЧТО ПРОВЕРЯЕТСЯ СЕЙЧАС

• Устойчивые признаки телефона, флешки или блокнота в предполагаемой
  области стола, с исключением деталей сейфа и оборудования.
• Предметы, оставшиеся в кадре после исчезновения распознанных людей.
• Возможное оставление банкнот после ухода человека из рабочей области,
  только когда имеющихся наблюдений достаточно для такого предположения.
• Позиционная роль кассира со стороны сейфа относительно стола. Принтер
  пока не используется как ориентир. Неоднозначные роли остаются неизвестными.
• Устойчивое присутствие посетителя, приход ещё одного посетителя при
  присутствии предыдущего и переход человека на сторону сейфа. Это поводы
  проверить запись: группа людей не равна нескольким обслуживаемым клиентам.
• Предметы после наблюдаемого ухода кандидата кассира к краю кадра,
  если на его стороне не видно замены. Присмотр вне кадра неизвестен.
• Непрерывно наблюдаемая открытая дверь от 3,5 секунды в изученном помещении.
  Неопределённые кадры прерывают интервал, поэтому возможны пропуски.

Это возможные признаки, а не подтверждённые нарушения. Стол, предметы и
люди могут быть распознаны неверно; личные вещи и роли клиентов не
устанавливаются. Содержимое пакета не определяется. Отсутствие эпизодов
не означает, что нарушений нет. Точный охват указан в отчёте по каждому
правилу и зависит от полноты обработки конкретной записи.

НЕ ПОДКЛЮЧЕНЫ НАДЁЖНЫЕ АВТОМАТИЧЕСКИЕ ПРОВЕРКИ

• Открытый сейф: экспериментальный модуль подключён, но пропускает открытые
  состояния на проверочных видео. Само открытие нарушением не считается;
  эпизод создаётся только при наблюдаемом уходе кандидата кассира. Закрытая
  дверца не доказывает запирания. Получение денег не устанавливается.
• Пересчёт и возврат остатка через счётчик. Таймлайн сырых наблюдений
  денег/карточек в JSON показывает пространственные связи; он не доказывает
  передачу, контакт с поверхностью, работу счётчика или принадлежность карты.
• Оригинальность удостоверения, завершение обслуживания, принадлежность
  документов прошлому клиенту, полномочия посетителя, тест периферии.
• Свет после ухода и оставленная без присмотра часть кабинета вне кадра.

ТЕХНИЧЕСКИЕ ДЕТАЛИ

Предметы проверяются автоматически каждые 0,5 секунды, люди — по всем
прочитанным кадрам, состояния — примерно каждые 0,25 секунды. Короткие
передачи между выборками могут быть пропущены; учащённая проверка рук пока
не подключена. Порог двери 3,5 секунды задан пользователем, не нормой НБРК.
Длительность устойчивости в эвристике не является разрешённым временем
нарушения. Маленькие флешки и банкноты распознаются экспериментально.
Уменьшение общего числа людей само по себе не считается уходом клиента.
Номера траекторий не устанавливают личности и могут меняться.

Время эпизода относится к исходной записи. Переход в проигрывателе учитывает
выборку кадров. WebM подготовлен для браузера; MP4 сохранён для скачивания.
При ошибке этапа остаются его журнал и результаты завершённых этапов.
При усечённом трекинге правила отсутствия людей отключаются.
При несопоставимом ракурсе состояния двери/сейфа остаются неизвестными.
Обновление страницы не останавливает анализ. Перезапуск сервера прерывает
незавершённые задания; для повторной проверки загрузите видео снова.

Программы и данные: D:\open\case.
Загруженные копии и результаты: web_data\jobs\<номер задания>.
Исходный пользовательский файл не изменяется. Загруженная копия хранится
локально, но в ZIP не включается. Данные автоматически не удаляются.
Видео не передаётся в облако. Адрес 127.0.0.1 доступен на этом компьютере.
Правила взяты из запроса пользователя и кейса; автоматической юридической
квалификации по актам НБРК или иной нормативной базе здесь нет.

ПРОВЕРКА КАЧЕСТВА
Состояния: training\visual_states\README_RU.txt и отчёты рядом.
На 54 отдельных проверочных кадрах дверь найдена на 11 из 14 открытых
кадров, ложных open нет; это малая выборка одного помещения. На двух целых
проверочных видео найдено одно открытие из двух, причём оно разбито на два
фрагмента. Сейф не распознал открытые проверочные примеры.
Оценка событий: evaluate_events.py и training\event_evaluation\README_RU.txt.
Имеющиеся метки «нарушение/время» не задают тип правила. Для оценки каждого
правила нужны отдельные размеченные интервалы и полностью проверенные
отрицательные записи. Необработанные видео не считаются верными ответами.
