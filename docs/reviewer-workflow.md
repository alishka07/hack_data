# Проверка результатов и оценка качества

## Работа проверяющего

Откройте сохранённый анализ в истории или загрузите видео. На компьютере видео и результаты расположены рядом. Фильтры показывают случаи, требующие проверки, подтверждённые случаи и весь список. Повторные наблюдения одного типа объединяются для просмотра, но исходные наблюдения сохраняются в подробностях. Диапазон наблюдений сам по себе не доказывает непрерывное присутствие объекта.

Нажатие на время открывает событие с контекстом до и после него. Проверьте исходные кадры и обоснование. Оно должно описывать видимое действие, а не предполагаемые намерения, принадлежность предметов или события за пределами кадра. «Не подтвердилось» и «Недостаточно данных» различаются: первое означает отрицательное решение по проверке, второе — невозможность сделать вывод.

Для каждого случая сохраните одно решение человека:

- **Подтвердить**: условия нарушения установлены по доступным доказательствам.
- **Отклонить**: проверка не подтверждает нарушение.
- **Недостаточно данных**: плохая видимость, неполный контекст или другая причина не позволяет вынести решение.

Добавьте комментарий и проверенные границы события. Если модель пропустила событие, добавьте его отдельно с типом и интервалом. Если несколько строк относятся к одному событию, задайте одинаковые проверенные границы. Разные пересекающиеся интервалы одного типа требуют уточнения перед расчётом полноты событий.

Полный просмотр видео подтверждайте только после проверки всей записи, включая промежутки без предложенных моделью событий. Укажите имя проверяющего, исходную группу, камеру и сессию. Проверка только найденных строк не устанавливает число пропущенных событий.

Решения человека сохраняются отдельно от результата модели. Они не меняют исходный вердикт, оценку модели, доказательства и версию анализа. «Следующий случай» позволяет продолжить проверку без поиска следующей строки.

## Отчёт в одном формате

Экспорт использует один формат: **самодостаточный HTML-файл**. В нём доступны сведения об анализе, обоснования, время, доказательные изображения и сохранённые решения проверяющего. Файл открывается браузером; для просмотра кадров не нужен работающий локальный сервер. Полное исходное видео в отчёт не встраивается.

В отчёте должны различаться исходный результат модели и последующее решение человека. Сохранённая копия отчёта представляет состояние на момент экспорта. После изменения проверки экспортируйте новую копию.

## Что означают показатели качества

`app/review_metrics.py` вычисляет показатели только из сохранённых решений человека. Непроверенные строки и «Недостаточно данных» не считаются отрицательными примерами. При пустом знаменателе возвращается `null`: интерфейс показывает «Недостаточно данных», а не 0%.

**Проверка кандидатов.** Отдельно указаны число подтверждённых и отклонённых человеком строк, неопределённых и непроверенных строк. Доля подтверждённых предложений относится к предложенным случаям, а не к точности всего детектора.

**Автоматическое решение модели.** Положительным решением считается только исходный `status: confirmed`. Найденный кандидатом случай со статусом `review_required` не является автоматически подтверждённым нарушением. Если человек подтвердил такой случай или случай `rejected`, это ложноотрицательное автоматическое решение. Подтверждённое моделью и отклонённое человеком нарушение — ложноположительное решение. Precision и `reviewed_candidate_recall` относятся только к решительно проверенным строкам; непроверенные части видео в их знаменатель не входят. True negative здесь — отклонённый кандидат, а не оценка всех нормальных промежутков видео.

**Известные пропуски.** Показаны подтверждённые человеком кандидаты, которые модель автоматически не подтвердила, и отдельно внесённые пропущенные события. Событие, повторно добавленное вручную и сопоставленное уже подтверждённому случаю того же типа, повторно не считается. Сопоставление использует проверенные интервалы или, при их отсутствии, исходную временную точку; оно взаимно однозначное. Поле `known_misses.total` суммирует пропущенные автоматические решения по строкам и отдельно добавленные события; это диагностическое число, а не полный подсчёт уникальных событий в видео.

**Полнота событий.** Event recall считается только в подмножестве видео, для которых проверяющий подтвердил полный просмотр, указал себя, исходную группу, камеру и сессию, вынес окончательное решение по каждой строке и указал положительные интервалы всех подтверждённых событий. Невалидные ручные события, неизвестные статусы модели и неоднозначные пересекающиеся интервалы исключают видео из этого знаменателя. Одинаковые интервалы одного типа считаются одним событием, даже если модель предложила несколько строк. Событие считается автоматически обнаруженным, если хотя бы одна соответствующая строка была исходно подтверждена моделью. В знаменатель также входят отдельно добавленные пропуски. Полнота этого проверенного подмножества не является оценкой непроверенных видео или внешней тестовой выборки.

**Временная локализация.** Temporal IoU вычисляется только когда и исходная модель, и проверяющий предоставили настоящие интервалы положительной длины. Отдельная временная точка, диапазон выборки кадров или отображаемый интервал повторных наблюдений не заменяет модельные границы события. Если модель возвращает только точки, средний IoU недоступен.

**Оценки модели.** Brier score и 10 интервалов диаграммы надёжности используют только конечные числа от 0 до 1 и окончательные решения человека. Принимаются `joint_checks` и `event_occurrence`, относящиеся ко всему проверяемому нарушению. `action_only`, `procedure_completion`, строки, логические значения и нечисловые оценки исключаются. Это исследовательский срез на проверенных примерах: сами вычисления не делают исходные оценки откалиброванными и не заменяют отдельную калибровочную выборку.

## Подготовка данных без утечки

`source_group` — общий идентификатор исходной записи и всех её аугментаций. Поворот, изменение света, обрезка, перекодирование и извлечение фрагмента не создают независимый источник. `camera_id` обозначает камеру, `session_id` — сессию записи. Идентификаторы должны быть последовательными во всей размечаемой коллекции.

Аудит строит связные группы по общим исходным семьям, точным SHA-256 и камерам/сессиям. Общая камера консервативно объединяет разные сессии: такой протокол подходит для проверки переноса на другую камеру. Для отдельного эксперимента переноса на новую сессию той же камеры нужен заранее установленный другой протокол; его результат нельзя называть переносом на новую камеру.

Манифест содержит хешированные идентификаторы групп и число записей. В нём нет названий видео, имён проверяющих и комментариев. Разделение автоматически не назначается: `partition` остаётся `unassigned`. Сначала зафиксируйте группы и независимый тест, затем разделяйте целые группы между обучением, валидацией и тестом. При неизвестной группе независимость не установлена. Если независимых групп меньше трёх, создать три независимые части пока нельзя. Для разных запусков анализа одной и той же записи в метриках выбирается одна наиболее свежая сохранённая проверка, чтобы повторная загрузка не увеличивала объём выборки. Аудит происхождения сохраняет связи всех запусков, включая исключённые точные дубликаты: смена метаданных при повторном анализе не разрывает общую исходную группу.

Далее соберите достаточное число независимо проверенных положительных и отрицательных случаев каждого типа, сложных чистых примеров и пропусков. Проверьте согласованность разметки вторым проверяющим. Не используйте результат модели как готовую обучающую истину. Аугментации применяются только после разделения исходников; тест не используется для выбора подсказок, порогов, настроек или эпох обучения. Новые правила требуют явных категорий и примеров, а проверка присутствия объекта требует своей разметки, если планируется обучение детектора.

## Состояние существующей коллекции

Сохранённый `docs/dataset-audit.json` описывает 42 исходные строки и 40 уникальных видео по байтовому хешу. В `open_labels.simplified.xlsx` есть слабые временные точки и бинарные метки, а не проверенные границы каждого события и полная разметка всех типов нарушений. Отсутствующая категория не означает отрицательную метку этой категории. Точная дедупликация не разделяет разные записи одной камеры или сессии.

Предыдущие обучающие эксперименты и их ограничения описаны в `docs/training.md`. Новая панель оценки не превращает прежние результаты в независимую тестовую точность и не запускает дообучение автоматически. До появления сохранённых решений человека соответствующие показатели остаются недоступными. Для оценки дообучения нужен заранее зафиксированный независимый набор с проверенными категориями, временными интервалами и происхождением аугментаций.

## Контракт агрегатора

`build_review_quality(records)` принимает список объектов:

```json
{
  "job_id": "job-1",
  "source_fingerprint": "SHA256 of source video, or empty if unavailable",
  "review_updated_at": "2026-10-18T10:00:00Z",
  "model_cases": [{
    "case_id": "stable-case-id", "type_id": "rule-id", "status": "confirmed",
    "timecode_sec": 10, "start_sec": null, "end_sec": null,
    "probability": 0.8, "probability_scope": "joint_checks"
  }],
  "review_state": {
    "revision": 1, "reviewer": "Проверяющий", "coverage_complete": true,
    "source_group": "original-family", "camera_id": "camera-1", "session_id": "session-1",
    "decisions": [{"case_id": "stable-case-id", "decision": "confirmed", "comment": "", "start_sec": 9, "end_sec": 14}],
    "missed_events": [{"event_id": "manual-1", "type_id": "other-rule", "start_sec": 30, "end_sec": 35, "comment": ""}]
  }
}
```

`review_updated_at` необязателен, также поддерживается `created_at`. При отсутствии временных меток более поздняя запись во входном списке имеет приоритет среди записей с сохранённой проверкой. Агрегатор возвращает `records`, `totals`, `per_type`, `grouping`, `limitations`. Исходные записи не изменяются. Имена, комментарии, описание сцены и пиксели не входят в агрегированный результат.

## Повторяемый запуск оценки

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_review_quality.py --db data/jobs.sqlite --output tmp/review-quality.json
```

Команда использует тот же адаптер `review_cases`, что и API, и читает SQLite в режиме `mode=ro` с `query_only`. Она не создаёт или мигрирует базу, не меняет результаты и отзывы, не запускает модель и не читает API-ключ. Для старых заданий без сохранённого SHA-256 хешируются только существующие файлы из каталога загрузок; хеш не записывается обратно в базу. При отдельном расположении базы и видео задайте `--uploads-dir data/uploads`.

JSON содержит только агрегаты и обезличенный аудит групп. Это технический результат повторяемой оценки, а пользовательский отчёт по анализу по-прежнему экспортируется только в HTML. При отсутствии проверенных решений консоль явно сообщает, что показатели недоступны, и соответствующие значения JSON равны `null`. Команда не подбирает пороги, не обучает калибратор и не выполняет дообучение.
